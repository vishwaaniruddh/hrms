## 2024-06-07 - Insecure Session Storage and Incomplete Session Termination
**Vulnerability:** Authentication tokens and user metadata were stored insecurely in `localStorage` which persists across tabs and sessions. Furthermore, the `removeUserSession` function failed to clear multiple critical session properties (such as `roleid`, `rolename`, `perm`, and `role_permission`), leaving stale and potentially dangerous metadata accessible after user logout.
**Learning:** This existed because of reliance on persistent storage (`localStorage`) instead of ephemeral storage (`sessionStorage`) for sensitive auth data. It was compounded by incomplete lifecycle management, where the removal function was not updated as new metadata fields were added to the session.
**Prevention:** Always use `sessionStorage` (or `HttpOnly` cookies where possible) for sensitive authentication tokens so that data is natively cleared when the browser session ends. Additionally, whenever new fields are added to session state, establish a process or unit test to ensure they are synchronously added to the corresponding session termination logic.
