## 2024-05-22 - [Incomplete Session Destruction & Insecure Storage Mechanism]
**Vulnerability:** Session data (tokens, IDs, roles, permissions) was stored in `localStorage`, which persists indefinitely across tabs and windows, increasing the attack surface for XSS. Additionally, `removeUserSession()` failed to remove half of the sensitive session metadata (roleid, rolename, perm, role_permission), leaving lingering authorization state on the client after logout.
**Learning:** Legacy utility files often have disjointed set/remove lifecycle functions. When variables are added to a "set" function later in the project's life, developers frequently forget to update the corresponding "remove" function, leading to session retention bugs.
**Prevention:** Always mirror keys directly between `set` and `remove` session operations. Transition long-lived session storage to `sessionStorage` (or HttpOnly cookies if backend is available) to minimize token exposure duration to the active tab lifecycle.
