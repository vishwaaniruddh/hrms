## 2025-05-27 - [Lingering Session Data & Insecure LocalStorage]
**Vulnerability:** Authentication credentials (tokens, roles) were stored in `localStorage`, exposing them to persistent token-theft risks (e.g., via XSS) across sessions. Additionally, the `removeUserSession` function cleared only 4 of the 8 authentication keys set during login, leaving sensitive role IDs and permission flags lingering in storage even after the user logged out.
**Learning:** Legacy session management scripts often overlook full cleanup when new attributes (like roles or permissions) are added to the login flow over time. Storing long-lived tokens in `localStorage` without `HttpOnly` cookie alternatives increases the attack surface for stolen sessions.
**Prevention:** Always verify that logout functions have perfect parity with login setter functions (all keys stored must be cleared). Default to `sessionStorage` for frontend-only credentials to ensure they are naturally destroyed when the tab or browser closes.
